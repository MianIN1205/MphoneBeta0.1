# 记忆模式：像人脑一样分区、像人一样想起来

> 2026-11-11 眠眠提的想法，还在研究阶段，什么都没做。这份是给新窗口接着想用的。
> 目标：让角色的记忆不只是「一条条文字按相似度捞出来」，而是像真人一样有不同的分区和记忆方式，回忆时像是在调用不同的感官（这是一种形容，不是真的让 AI 调用什么）。

---

## 一、人脑大概怎么安排记忆（简化版）

大方向是公认的，细节学界还在研究，这里只当借鉴的结构，不追求严格。

| 分区 | 是什么 | 例子 |
|---|---|---|
| 工作记忆 | 眼前正在想的几件事，容量很小，很快就散 | 刚才那几句聊天 |
| 情景记忆 | 某一次发生的事，带时间、地点、当时的感觉 | 那天在病房，蚊子很多，她说想回家 |
| 语义记忆 | 很多次经历沉淀下来的事实，不记得哪天知道的 | 她不吃菌菇；她喜欢三分糖热奶茶 |
| 程序记忆 | 变成习惯的东西，不用回想，直接体现在做法里 | 她难受时先抱，再说 |
| 情绪标记 | 情绪越强记得越牢；人在某种心情里更容易想起同样心情下的事 | 委屈的时候想起以前委屈的事 |
| 感官碎片 | 一段记忆的画面、声音、气味分散存着，一个线索能把整段带回来 | 闻到某种味道，整个下午都回来了 |
| 巩固和淡化 | 睡觉时整理白天的事；细节慢慢淡、留下大意；常被想起的更牢；每次想起都会被轻轻改写 | 很久以前的事只记得个大概 |
| 联想 | 想起一件事，顺带想起和它连着的另一件 | 想起福州，就想起那朵蓝色的花 |

## 二、小手机现在的记忆是什么样

相关文件：`js/char/memory.js`（记忆本体）、`js/desk/memory-lib.js`（记忆库界面）、`js/desk/memory-hub.js`（和记忆库同步）、`memory-hub/src/index.js`（部署在 Cloudflare 的记忆库）。详细说明见 `CLAUDE.md` 的 memory 一行。

- 一条记忆：`{ id, type: short / long / precious, text, time, source, scene, from, hubKind, hubSrc, emb }`，存在 `memStore[角色id]`。
  - 短期 300 字、几天后自动忘；长期 / 珍贵最多 2000 字（`MEM_TEXT_MAX`）。
- 记下：角色在回复里写 `<记忆 类型="长期">…</记忆>`（`memExtractTags`），或者用户手动加、日记、导入的聊天记录整理。
- 想起（`memoryContextFor`）：
  - 珍贵的最近 12 条每次都带；
  - 其余按和最近聊天的相似度挑 `topK` 条（本地按字算余弦，或者开了向量记忆用向量）；不够就用最近记的补；
  - 关系里程碑一直带；
  - 总量按「记忆最多占用」（`budget`，默认 6000 token）裁。
- 别的地方也有类似「记忆」的东西：`char.selfFacts`（聊出来的设定）、世界书「写法要求」、剧情存档 `char.dramaSaves`、TA 的今天 `mphone_char_days`、待关心 `char.followUps`。

**现在的问题**：所有记忆都在一个池子里、一种想起方式（按字面像不像）。事实、经历、习惯混在一起；想起来的只是一段文字，没有「当时的感觉」；很久以前的和昨天的同等对待。

## 三、对应关系和现状

| 人脑 | 小手机里对应什么 | 现在有没有 |
|---|---|---|
| 工作记忆 | 最近的聊天记录（注意力范围） | 有 |
| 情景记忆 | 一件件带时间的记忆 | 有 |
| 语义记忆 | 关于她的事实、聊出来的设定 | 有，但和事件混在一个池子里 |
| 程序记忆 | 相处方式，一直生效、不用「想起」 | 有，就是世界书的「写法要求」 |
| 情绪标记 | 每条记忆带情绪 | 没有 |
| 感官碎片 | 每条记忆带几个线索 | 没有 |
| 巩固和淡化 | 常想起的更牢，久了只剩大意 | 没有 |
| 联想 | 想起一件带出相关的一件 | 没有 |

## 四、可以怎么做（草稿，等眠眠定）

### 1. 情绪标记
- 每条记忆加 `emo`：一两个词，从一个小词表里选（甜 / 心疼 / 委屈 / 生气 / 害怕 / 安心 / 好笑 / 想念 / 害羞 / 难过 …），再加一个强度 `emoW` 1～3。
- 想起时：先猜她现在的心情（看最近几条她的话，用同一个词表；可以用关键词粗判，不另外请求），心情对得上的记忆加分；强度高的本来就更容易被想起。
- 珍贵记忆里强度最高的几条，即使不相关也偶尔浮上来（像人会突然想起某件事）。

### 2. 感官线索
- 每条记忆加 `cues`：3～6 个具体的东西，偏感官（看到的、听到的、闻到的、吃到的、摸到的），比如「三分糖热奶茶」「病房的蚊子」「蓝色的花」「硬座」「雨天」。
- 她这次说的话里出现了线索（或很像），这条记忆直接被唤起，不管文字整体像不像。
- 想起时给 TA 看的样子从「· 一段文字」改成带画面的写法，比如：
  `想起来了：〔那天的画面：病房、蚊子、她说想回家〕……（心疼）`
  让 TA 回忆时有「当时的感觉」，而不是背资料。

### 3. 分区
- 加一个 `zone`：经历（情景）/ 关于她（语义）/ 关于我自己 / 我们之间。
- 关于她的事实不按相似度捞，而是常驻一小段「我知道的她」（压缩成要点，控制在几百字），像人不用回想就知道对方不吃什么。
- 程序记忆继续交给世界书「写法要求」，不进记忆池。

### 4. 巩固和淡化
- 每条记忆记 `hits`（被想起过几次）和 `lastHit`。
- 常被想起的更容易再被想起；很久没被想起的长期记忆，平时只给大意（存一句 `gist`），线索对上了才给完整的。
- 「睡眠整理」：每天一次（可以接在写日记那个时间点），把当天的短期记忆里重要的升成长期、补上情绪和线索、写一句大意。这一步要花一次请求。
- 「每次想起都会被改写」先不做，容易把记忆改坏。

### 5. 联想
- 每条记忆可以有 `links`：和它相连的几条的 id（同一个线索、同一个人、同一段时间）。
- 想起一条时，有一定概率带出一条相连的，标成「顺带想起」。

## 五、代价和要注意的

- **钱**：新记的记忆，情绪 / 线索 / 大意让 TA 在 `<记忆>` 标签里顺手写（加属性），和回复同一次请求，不多花。已有的记忆要一次性补标签，几十条大概几次请求。睡眠整理每天一次。
- **提示词长度**：线索和情绪会让每条记忆变长一点；靠「平时只给大意」省回来。
- **同步**：新字段要能进记忆库（放 `meta` 里就行，记忆库那边不用改表），别的小手机通过 MCP 拿到时也能看到情绪和线索。
- **兼容**：旧记忆没有这些字段时照现在的方式想起，不能坏。
- **不编造**：补标签时只能从记忆原文里找线索，不能编没写过的细节（用户的铁律：绝不编造）。
- **只是借结构**：做出来是「回忆的方式更像人」，不是真的大脑；像不像要用了才知道。
